# Windows 10/11 编译 ipmitool 1.8.19：Cygwin 报错排查与便携版制作完整记录

本文记录一次实际成功的 `ipmitool 1.8.19` Windows 编译过程，包括 Cygwin 环境准备、依赖选择、源码编译、连续多次报错定位与修复、Libtool wrapper 识别、DLL 依赖分析，以及最终整理成可以复制到其他 Windows 10/11 x64 电脑直接使用的便携版本。

本文由 [anssl](https://anssl.cn/) 实际编译、测试并整理。

## 项目信息

- 上游项目：[ipmitool](https://github.com/ipmitool/ipmitool)
- 源码版本：`1.8.19`
- 源码仓库：[https://github.com/ipmitool/ipmitool](https://github.com/ipmitool/ipmitool)
- Windows 编译：[anssl](https://anssl.cn/)
- 构建平台：Windows 10 x64 / Cygwin x86_64
- 构建类型：Windows x64 Cygwin 便携版
- 实际编译日期：2026-08-11

> 本文记录的是基于上游 `ipmitool` 源码自行编译、排错和整理便携版本的过程，并非上游项目官方发布的 Windows 二进制版本。源码版权及许可证以 `ipmitool` 上游仓库中的许可文件为准。

```text
ipmitool-1.8.19-win64\

├── cygwin1.dll
```

本次主要用途：

```text
Windows
  ↓
IPMI 2.0 / RMCP+
  ↓
BMC
  ↓
标准 RAW / OEM RAW
```

例如：

```cmd
ipmitool.exe -I lanplus -H BMC_IP -U USER -a mc info
```

以及：

```cmd
ipmitool.exe -I lanplus -C 17 -H BMC_IP -U USER -a raw 0x06 0x04
```

需要注意：

- `lanplus`：可用；
- `raw`：可用；
- `-C 17`：可用于指定 Cipher Suite 17；
- `open`：不可用，这是 Windows+Cygwin 下的正常现象。

`open` 是 Linux OpenIPMI/KCS 本机接口，一般依赖 `/dev/ipmi*`，不是本次 Windows 网络访问 BMC 的目标。

# 十一、错误一：`strptime` 未声明

第一次真正的错误：

```text
ipmi_sel.c:2762:21: error: implicit declaration of function 'strptime'; did you mean 'strftime'? [-Wimplicit-function-declaration]
```

对应源码：

```c
if (strptime(time_string, time_format, &tm) != NULL) {
```

最初尝试过：

```bash
CPPFLAGS="-D_XOPEN_SOURCE=700" ./configure
```

它可以让 `strptime()` 声明出现，但后来证明不能全局使用，因为会影响其他源码文件，尤其会引出 `usleep()` 的兼容问题。

最终方案是：

> `_XOPEN_SOURCE=700` 只放进 `lib/ipmi_sel.c`，不设置成整个工程的全局 CPPFLAGS。

后文会统一修改。

---

# 十二、错误二：`strcasecmp` 未声明

继续编译后出现：

```text
error: implicit declaration of function 'strcasecmp'
```

`strcasecmp()` 的声明在：

```c
<strings.h>
```

而原来的：

```text
lib/ipmi_sdr.c
```

只有：

```c
#include <string.h>
```

执行：

```bash
sed -i '/^#include <string.h>/a #include <strings.h>' lib/ipmi_sdr.c
```

检查：

```bash
grep -n -A2 -B2 "strings.h" lib/ipmi_sdr.c
```

正确结果类似：

```text
37-#include <string.h>
38:#include <strings.h>
39-
40-#include <math.h>
```

这个修改最终保留。

# 十四、错误四：`usleep` 未声明

```text
ipmi_sol.c:1455:25: error: implicit declaration of function 'usleep'; did you mean 'sleep'? [-Wimplicit-function-declaration]
```

# 十七、只给 `ipmi_sel.c` 定义 `_XOPEN_SOURCE=700`

原源码中存在：

```c
#define __USE_XOPEN /* glibc2 needs this for strptime */
```

最终把它删除，改成：

```c
#define _XOPEN_SOURCE 700
```

并且必须放在系统头文件之前。

先清理：

```bash
sed -i '/^#define __USE_XOPEN/d;/^#define _XOPEN_SOURCE 700$/d' lib/ipmi_sel.c
```

再插入：

```bash
sed -i '/^#include <string.h>/i #define _XOPEN_SOURCE 700' lib/ipmi_sel.c
```

检查：

```bash
sed -n '30,42p' lib/ipmi_sel.c
```

本次最终正确内容：

```c
/*
 * ...
 */

#define _XOPEN_SOURCE 700
#include <string.h>
#include <strings.h>
#include <math.h>
#include <time.h>
#include <ctype.h>
#include <errno.h>
#include <stdbool.h>

#include <ipmitool/helper.h>
```

关键点：

```text
_XOPEN_SOURCE=700
```

只作用于：

```text
lib/ipmi_sel.c
```

而不是整个工程。

# 二十、又一个坑：`src/ipmitool.exe` 并不是真正的最终程序


可能不会得到正常输出，因为 wrapper 找不到 `.libs` 目录中的真正程序。


# 二十六、执行 OEM / 定制 RAW

只要厂家的定制命令本质仍然是：

```text
NetFn + Command + Data
```

就可以通过：

```text
raw
```

直接发送。

例如厂家命令：

```text
raw 0x30 0x90 0x01 0xff
```

执行：

```cmd
ipmitool.exe -I lanplus -C 17 -H 192.168.1.100 -U ADMIN -a raw 0x30 0x90 0x01 0xff
```

需要注意，`ipmitool` 能发 RAW，并不意味着所有 OEM RAW 都必然允许通过网络执行。

具体可能存在：

```text
允许 lanplus 直接执行
需要 IPMB bridge / target address
只允许物理主板本机 KCS 执行
```

这取决于具体 BMC 和主板厂商实现。

# 二十七、最终保留的源码修改

真正需要保留的兼容修改主要有三类。

## 1. `lib/ipmi_sdr.c`

增加：

```c
#include <strings.h>
```

命令：

```bash
sed -i '/^#include <string.h>/a #include <strings.h>' lib/ipmi_sdr.c
```

解决：

```text
strcasecmp() 未声明
```

## 2. `lib/ipmi_sel.c`

删除：

```c
#define __USE_XOPEN
```

改为：

```c
#define _XOPEN_SOURCE 700
```

命令：

```bash
sed -i '/^#define __USE_XOPEN/d;/^#define _XOPEN_SOURCE 700$/d' lib/ipmi_sel.c
sed -i '/^#include <string.h>/i #define _XOPEN_SOURCE 700' lib/ipmi_sel.c
```

解决：

```text
strptime() 未声明
```

## 3. `lib/ipmi_sel.c`

将：

```c

```

替换为：

```c
strchr(...)
```

命令：

```bash
sed -i 's/\<index\>(/strchr(/g' lib/ipmi_sel.c
```

解决：

```text
index() 未声明
```

# 二十八、不要全局设置 `_XOPEN_SOURCE=700`

下面这个方案虽然能解决 `strptime()`：

```bash
CPPFLAGS="-D_XOPEN_SOURCE=700" ./configure
```

但是会影响整个工程。

本次实际导致：

```text
ipmi_sol.c: error: implicit declaration of function 'usleep'
```

如果已经执行过，需要清除：

```bash
unset CPPFLAGS
make distclean
rm -f config.cache config.status config.log
./configure CPPFLAGS=''
```

然后检查：

```bash
grep -n '^CPPFLAGS' Makefile lib/Makefile
```

必须是：

```text
CPPFLAGS =
```

# 二十九、相同环境下重新编译的简化流程

如果以后重新下载一份干净的 `ipmitool 1.8.19`，在同类 Cygwin 环境下可以直接按下面流程处理。

进入源码：

```bash
cd /cygdrive/c/ipmitool-IPMITOOL_1_8_19
```

处理换行：

```bash
dos2unix bootstrap configure.ac csv-revision
chmod +x bootstrap csv-revision
```

生成构建系统：

```bash
./bootstrap
```

应用兼容修改：

```bash
sed -i '/^#include <string.h>/a #include <strings.h>' lib/ipmi_sdr.c
sed -i '/^#define __USE_XOPEN/d;/^#define _XOPEN_SOURCE 700$/d' lib/ipmi_sel.c
sed -i '/^#include <string.h>/i #define _XOPEN_SOURCE 700' lib/ipmi_sel.c
sed -i 's/\<index\>(/strchr(/g' lib/ipmi_sel.c
```

清除可能存在的环境变量：

```bash
unset CPPFLAGS
```

配置：

```bash
./configure CPPFLAGS=''
```

检查：

```bash
grep -n '^CPPFLAGS' Makefile lib/Makefile
```

编译：

```bash
make 2>&1 | tee build.log
```

检查错误：

```bash
grep -n -i "error:" build.log
```

验证：

```bash
./src/ipmitool.exe -V
```

找到真正 EXE：

```bash
ls -lh src/ipmitool.exe src/.libs/ipmitool.exe
```

检查真正程序的 DLL：

```bash
cygcheck ./src/.libs/ipmitool.exe
```

最后根据 `cygcheck` 实际结果打包运行库。

# 三十、常见问题

## 1. 出现大量 warning 是否代表失败？

不一定。

例如：

```text
warning: 'supermicro_x8' defined but not used
warning: 'supermicro_p8' defined but not used
warning: array subscript has type 'char'
```

这些都是警告。

真正判断编译失败原因，应搜索：

```bash
grep -n -i "error:" build.log
```

---

## 2. 为什么 Make 只显示 `Error 1`、`Error 2`？

例如：

```text
make[2]: *** [Makefile:532: ipmi_sel.lo] Error 1
make[1]: *** [Makefile:486: all-recursive] Error 1
make: *** [Makefile:418: all] Error 2
```

这只是上层 Make 任务失败。

真正的 C 编译器错误通常在前面。

直接：

```bash
grep -n -B 8 -A 12 -i "error:" build.log
```

---

## 3. 为什么 Cygwin 中能运行，复制到 CMD 后不行？

很可能复制错了：

```text
src/ipmitool.exe
```

它可能只是 Libtool wrapper。

真正程序通常是：

```text
src/.libs/ipmitool.exe
```

本次实际大小：

```text
src/ipmitool.exe        26 KB
src/.libs/ipmitool.exe  2.9 MB
```

---

## 4. 这个版本是不是一个单独 EXE？

不是。

本文构建的是：

```text
Windows x64 Cygwin 便携版
```

需要：

```text
ipmitool.exe
+ 若干 Cygwin DLL
```

但目标 Windows 无需安装完整 Cygwin。

如果目标是：

```text
只有一个 ipmitool.exe
```

则需要另行使用 MinGW-w64 并静态链接 OpenSSL 等依赖。

---

## 5. PVE 中的 Windows 10 虚拟机会不会影响使用？

对于：

```text
-I lanplus
```

不会。

只要 Windows 虚拟机能够访问 BMC IP，就可以正常工作。

但是：

```text
-I open
```

属于物理主板本机的 KCS/OpenIPMI 路径，虚拟机默认无法直接看到 PVE 宿主机物理主板的 KCS 设备。

# 三十一、完整排错时间线

本次真正经历的顺序如下：

```text
安装 Cygwin
    ↓
安装 gcc / make / autotools / OpenSSL 等开发包
    ↓
./bootstrap
    ↓
./configure
    ↓
确认 lanplus : yes
    ↓
第一次 make
    ↓
strptime() 未声明
    ↓
尝试全局 -D_XOPEN_SOURCE=700
    ↓
strcasecmp() 未声明
    ↓
ipmi_sdr.c 增加 <strings.h>
    ↓
index() 未声明
    ↓
index() → strchr()
    ↓
usleep() 未声明
    ↓
发现 Makefile 仍全局保存 -D_XOPEN_SOURCE=700
    ↓
make distclean
    ↓
清除 config.cache / config.status / config.log
    ↓
CPPFLAGS 重新置空
    ↓
_XOPEN_SOURCE=700 仅放进 ipmi_sel.c
    ↓
重新 make
    ↓
grep error 无输出
    ↓
ipmitool version 1.8.19
    ↓
发现 src/ipmitool.exe 只有 26 KB
    ↓
确认它是 Libtool wrapper
    ↓
找到 src/.libs/ipmitool.exe（2.9 MB）
    ↓
cygcheck 检查真正 EXE
    ↓
发现 5 个 Cygwin DLL 依赖
    ↓
整理 Windows 便携目录
    ↓
普通 Windows CMD 验证通过
```

整个过程中最重要的经验有两个：

第一，不要只看 Make 最后的：

```text
Error 1
Error 2
```

一定要保留：

```text
build.log
```

然后搜索真正的：

```text
error:
```

第二，修改旧项目的 feature-test macro 时，不要轻易把：

```text
_XOPEN_SOURCE
```

全局应用到整个工程。解决一个源码文件的问题，可能同时让另一个源码文件的旧 POSIX 接口消失。
